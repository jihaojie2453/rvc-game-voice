## 1. 项目是什么

**Android 实时 RVC 变声 App**（包名 `com.voicestudio.phone`，版本 0.6.7 / versionCode 26）。
把手机麦克风的声音实时转换成某个 RVC 音色，然后**注入到游戏的语音输入**里——
队友听到的就是变声后的声音，而游戏本身检测不到注入（无 ptrace、无 root 注入到游戏进程）。

```
麦克风 → 16 kHz → HuBERT(特征) + RMVPE(音高) → enc(隐变量) → dec(NPU) → 48 kHz
                                                              ↓
                                              虚拟麦（音频策略注入）→ 游戏语音
```

界面分四页：**状态**（选游戏/模型/方案，开虚拟麦）、**配置**（音色与引擎参数）、
**试听**（本地监听，不经过游戏）、**通用**（计算设备、模型导入、语言）。
另有**音频**页用于播放本地素材并变声。

## 3. 音频链路细节

### 3.1 两条路径

| | 试听（返音）| 游戏（虚拟麦）|
|---|---|---|
| 采集 | `LiveEngine` 里直接 AudioRecord | 桥接进程采集，经 socket 送到 App |
| 处理 | 同一个 `LiveCore` | 同一个 `LiveCore` |
| 输出 | AudioTrack → 你的耳机/扬声器 | 注入轨 → 游戏语音输入 |
| 后处理 | **无** | 游戏自己的 AGC / 降噪 / 编码 |

**这是"游戏里和返音听起来不一样"的根本原因**：返音是直通，游戏还要过它那一整套处理
（能量重算、频谱改造、十几 kbps 编码）。这段不归我们控制。

### 3.2 虚拟麦原理（注入）

```
app_process（shell uid 2000）启动 Java 桥接
  → AudioManager.registerAudioPolicy
  → MIX_ROLE_INJECTOR + RULE_MATCH_UID + ROUTE_FLAG_LOOP_BACK
  → 用 REMOTE_SUBMIX 采集到"游戏以为的麦克风"
  → 我们往里写转换后的 48 kHz 单声道 PCM16
```

不对游戏进程做任何 ptrace / hook，所以 `TracerPid` 干净、不触发反作弊。

### 3.3 `LiveCore.step()` 内部顺序（`Live.kt:188`）

```
1. 跳过判定 blockIsQuiet(...)  → 整块输出数字静音（省电）
   ★ 但 holdLeft > 0（刚说完话 0.3 s 内）不许跳过，否则尾音被硬切
2. 48k → 16k：downsampler.process(x48, b48)   ★ 返回的是"整窗"，不是新块
3. rvc.streamWindow(x16, ...)                 → 特征/音高/enc/dec
4. SOLA 对齐 + 80 ms 交叉淡化
5. 逐 10 ms 帧的门限（gate）：超过阈值开、保持 0.3 s、50 ms 淡出
6. softClip + 增益 → 输出
```

**重要约束**：16 kHz 那一层是**重叠窗口**（相邻两次大面积重叠），任何有状态的流式算法
（降噪、回声消除）都不能插在那里，必须插在 48 kHz 采集侧、进 `ring` 之前。

### 3.4 参数语义（用户最常调的部分）

| 参数 | 作用 | 陷阱 |
|---|---|---|
| `pitch` | 音高移调（半音）| 超过 +14 会明显"尖 + 沙哑"，是模型舒适区问题 |
| `formant` | 共振峰；改变会**拉伸隐变量并重采样输出** | 非 0 会增加合成痕迹；负值偏低沉、正值偏亮 |
| `intonation_ratio` | 语调放大 | 过大会出机械感 |
| `intonation_expand` | 语调夸张开关 | 用户最终开了它来找"柔和" |
| `rms_mix_rate` | 0 = 输出音量跟随输入块 | **非 0 会把模型在被压静音的输入上生成的气声放大**，慎用 |
| `unvoiced_keep` | 浊音保持（填气声）| 开关对噪声影响有限 |
| `live_threshold_db` | 静音门限 | 摩擦噪声比它高 30 dB，门限对摩擦无效 |
| `live_input_gain_db` | 输入增益 | 过热会让 softClip 压弯，听起来"炸" |
| `live_gain_db` | 输出增益（下限已放到 −24）| 游戏侧 AGC 会二次调整 |
| `live_block` | 每步推进（10 ms 单位）| 越小越实时、越费 CPU |
| `live_context` | 上下文长度（10 ms 单位）| 越长越连贯 |
| `live_crossfade` | 交叉淡化（10 ms 单位）| |
| `live_cushion_cs` | 输出缓冲（**10 ms 单位**）| 太小吸收不了计算尖峰 → "咯痰"；现在 150 ms |

## 4. 已解决的问题（全部是踩过的坑，**不要回退**）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 40k 模型导入后不显示 | 目录权限 `drwxrwx--- shell` | `chmod -R a+rwX` |
| 2 | 40k 模型输出全是噪声 | ncnn 只认 `frames*320/480` | `ncnn_decoder.cpp` 改成按 `ns % frames` 推 hop |
| 3 | 40k 模型卡顿 | 没有 NPU 解码器 → 退 CPU | 生成 `model.dec.w8a16.onnx`（calib 用用户自己的录音）|
| 4 | 摩擦噪声变多（相对 11-15 版本）| 噪声底被改成 ±1 LSB，游戏 VAD 行为变了 | **恢复 ±15**（`AppBridge.noiseFloor()`）|
| 5 | 开口第一个字被吞 | 旧逻辑攒满 `idleBlocks` 后**无条件跳过**，不管当前块 | 改为只看当前块是否整块低于门限 |
| 6 | 功耗升高、游戏掉帧 | 跳过条件改成"整个 1.6 s 窗口都安静"，有环境噪声就永不跳过 | 改回"只看当前块" |
| 7 | 最后一个字说一半就没了 | 跳过整块输出数字静音，**绕过了门限的 0.3 s 保持** | 跳过加条件 `holdLeft <= 0` |
| 8 | 声音"咯痰"（突发失真）| 计算偶尔尖峰 346 ms > 块长 270 ms → 缓冲抽干 → 插 180 ms 静音 | 输出缓冲 60 → 150 ms |
| 9 | 返音 CPU 解码负载 248% | 调试期把 `w8a16`/`ncnn` 改名成 `.off`，App 退到 CPU | 恢复文件名 |
| 10 | 电音/机械感 | 音高过高（295 Hz，超出模型舒适区）+ 共振峰拉伸 | 降回 +11～12、关掉拉伸 |

RNNoise 接在 **48 kHz 采集侧、进 `ring` 之前**（游戏与试听各一份状态），开关在配置页「高级设置 →

## 7. 调试方法论（这套很好用，别丢）

### 7.1 日志

```
试听   files/live_log.txt                     每次会话结束写 summary
游戏   files/virtual_mic/<epoch>/session.log  CONFIG / STREAM / BRIDGE_*
       files/virtual_mic/<epoch>/blocks.csv   逐块：compute/输入输出峰值/是否跳过
       files/virtual_mic/root-<epoch>.log     桥接侧：gap/trimmed/underruns/queue
```

读法要点：
- `blocks.csv` 的列格式见 `Live.kt:390`
- 跳过步的 `input_peak` 记的是**整个窗口**的峰值（不是当前块），别误读
- `session.log` 的 `CONFIG` 行是判定"两边参数是否一致"的关键
- 读 App 私有目录需要 root：`su -c 'cp ... /data/local/tmp/测试/'`

### 7.2 抓"注入给游戏的音频"

```sh
su -c 'touch /sdcard/Android/data/com.voicestudio.phone/files/debug_trace'
# ★ 必须完全关掉虚拟麦再重开（桥接进程只在启动时读这个开关）
```

产出 `/data/local/tmp/root-<epoch>`（输入）与 `.injected.wav`（注入）。
**注意**：WAV 头长度字段是 0，Python `wave` 会拒绝，要自己按 `data` 块读到底。

### 7.3 离线对拍（非常有价值，能脱离手机定位问题）

电脑上可以直接跑同样的 ONNX 链路做"标准答案"：

```python
hubert.onnx   audio[1,N]@16k        → features[1,frames,768]     (50 fps)
rmvpe.onnx    audio[1,N]@16k        → salience[1,frames,360]     (100 fps)
enc.onnx      phone,pitch,noise     → z[1,192,T]
dec.onnx      z, sine               → 40k 音频
```

- RMVPE 的 360 格 → 频率：`CENTS[i] = 0 if i<4 or i>=364 else 20*(i-4)+1997.3794`，
  `f0 = 10 * 2 ** (cents/1200)`（见 `Rvc.kt:532` `decodeF0`）
- 音高 token：mel 映射到 1..255（见 `Rvc.coarse`，`Rvc.kt:592`）
- **激励生成必须逐采样累加相位**（`Rvc.kt:605` `nsfSource`）：
  每帧 `phase += f0/sampleRate` 逐样本推进；写成"逐帧相位后重复"会得到一堆气声
- 这个对拍帮我们确认过：**离线干净 → 问题在手机实时链路**；离线也脏 → 问题在模型

### 7.4 常用分析脚本思路

- 尾音：`blocks.csv` 里 `convert→skip` 之前 3 步的 `output_peak` 是否递减
- 摩擦：摩擦段 `input_peak − output_peak` 的中位值
- 电音/机械感：算振幅包络调制谱（找 37 Hz 块率峰）、F0 抖动、谐噪比、LTAS 与目标音色对比

## 10. 术语对照

| 说法 | 含义 |
|---|---|
| 返音 / 试听 | `LiveEngine` 本地监听，不经过游戏 |
| 虚拟麦 / 注入 | 桥接 + 音频策略，把转换结果喂给游戏 |
| 吞字 | 起音或尾音被切掉（门限或跳过造成）|
| 咯痰 | 计算尖峰导致缓冲抽干，插入一段静音 |
| 电音 / 机械感 | 合成痕迹，多与音高超出模型舒适区、共振峰拉伸有关 |
| 摩擦 | 被子/衣服摩擦麦克风产生的宽带噪声 |
| 方案 | profile，一套 voice + engine 参数 |
